# Wall-E PCB 引脚需求

> 基于 `wall-e_xiaozhi`（主控）和 `wall-e_esp32_cam`（CAM 模组）实机调通结果整理。
> 当前 PCB 存在 3 处 GPIO 冲突，新设计需解决。

## 二、CAM 模组 艾尔赛 ESP32CAM_V1.1（303ESPCAM01，OV3660 实机确认）

要求：ESP32-S3 带 **8MB PSRAM / 16MB Flash**（眼屏 framebuffer 需 115KB），
摄像头 OV3660（DVP 接口，实机 PID 0x3660），板载 Wi-Fi 天线。
厂商资料见 `hardware/ESP32S3_CAM/`；**模块仅在两排 8P 排针上引出 GPIO 0/2/14/21/41/42/45/46**（JP1: EN/43/44/3V3/GND/BOOT/IO2/3V3；JP2: 5V/GND/46/45/42/41/21/14），这是下文所有引脚选择的硬约束。

### 2.1 眼屏 ×2（1.28" GC9A01 圆屏，共享 SPI3）

| 信号 | 当前引脚 | **新 PCB** | 说明 |
|------|---------|-----------|------|
| SCK  | 42 | 42 | 共享 SPI 时钟 |
| MOSI | 45 | 45 | 共享 SPI 数据 |
| DC   | 41 | 41 | 共享 数据/命令 |
| RST  | 46 | 46 | 两屏共享复位 |
| CS_L | **2** | 2 | 模块仅引出此脚，无法改；CS 空闲高，与任何外设不冲突 |
| CS_R | **0** | 0 | 模块仅引出此脚（BOOT），strapping 但 CS 空闲高，已实机验证可正常启动 |
| VDD  | 3V3 | 3V3 | |
| GND  | GND | GND | |
| TE   | 未接 | — | 无法接：TE 需要空闲 GPIO，但模块引出脚全部占用 |

> CS 空闲高、SCK 空闲低一般无碍。**GPIO46 做 RST 输出已在当前板上验证通过。**

### 2.3 SD 卡（结论：本模块不可用）

板载 TF 卡槽（原理图 J1）实接（SDMMC 模式，D2/D3 仅 10K 上拉未接 MCU）：

| 信号 | 引脚 | 说明 |
|------|------|------|
| SD_CLK   | **GPIO39** | MTCK |
| SD_CMD   | **GPIO40** | MTDO |
| SD_DATA0 | **GPIO41** | MTDI |
| SD_DATA1 | **GPIO42** | MTMS |
| SD_DATA2 / DATA3 | NC | 仅上拉 |

> ⚠️ **SD 不可用**：① CLK(39)/CMD(40) 未在模块排针上引出；② D0(41)/D1(42) 与眼屏 DC(41)/SCK(42) 冲突；③ DATA3 未接 → SPI 模式也无 CS 可用。除非直接飞线焊 WROOM 模组焊盘，否则 SD 卡无法工作。**此前文档"SD 与摄像头共用 GPIO8/9"的说法源于固件里 XIAO 旧预设（SPI: 2/7/8/9），对本模块不成立——摄像头 DVP 与 SD 实际无引脚冲突。** 拍照/录像走 HTTP 从 PSRAM 取，不落本地 SD。

### 2.7 冲突清单（复查结论）

| # | 原记录冲突 | 复查结果 |
|---|-----------|---------|
| 1 | 眼屏 CS_L vs SD CS（GPIO2） | **不成立**：本模块 SD 无 CS 脚（SDMMC，DATA3 未接），GPIO2 仅用于眼屏 CS_L |
| 2 | 摄像头 Y3 vs SD MOSI（GPIO9） | **不成立**：SD 引脚实为 39/40/41/42，与 DVP 无冲突；"9"是固件 XIAO 旧 SPI 预设 |
| 3 | 摄像头 Y4 vs SD MISO（GPIO8） | **不成立**：同上 |
| 4 | 眼屏 CS_R（GPIO0）strapping | **属实但无解**：模块仅引出 GPIO0，CS 空闲高已实机验证可正常启动，保持 2/0 即可 |

> 结论：本模块不存在可解决的 GPIO 冲突；**SD 卡整体不可用**（见 2.3），眼屏引脚 0/2/41/42/45/46 为该模块排针引出的唯一可行选择。

## 三、全局约束

### 3.1 Strapping 引脚注意事项

ESP32-S3 以下引脚上电时有特殊功能，PCB 设计需确保外设默认电平不干扰启动：

| GPIO | 启动功能 | 当前用途 | 风险 |
|------|---------|---------|------|
| 0 | 启动模式（低=下载） | 按键 + 眼屏 CS_R | 上电如被拉低进下载模式 |
| 3 | JTAG | 4G 保留 | 低 |
| 45 | VDD_SPI 电压 | 眼屏 MOSI | 上电需高阻/高电平 |
| 46 | ROM 日志 | 眼屏 RST | 已调通，输出模式无碍 |

### 3.2 硬件设计建议

- **眼屏引脚固定为 0/2/41/42/45/46**（该模块排针仅引出这些 IO），CS_R=0 需保证 CS 空闲高（上电不被拉低）
- **SD 卡不可用**：模块引出脚已全部占用，无 SD 可用引脚；拍照/录像不落本地 SD
- **眼屏 TE 帧同步无法接**（无空闲 GPIO），如需防撕裂可在驱动层按全帧刷新处理
- **两颗 ESP32-S3 均需 8MB PSRAM**（主控 N16R8、CAM 8M PSRAM/16M Flash）
- **主控 USB D-/D+（GPIO19/20）被占用**，调试口走 UART0 引出排针
- **摄像头 OV3660 DVP 并口** 8 条数据线需等长布线
- **共地**：主控与 CAM 的 UART 需共地
